Runtime check method for the statuses. The issue's "Done when" asks for a runtime check of each duration, so the plan must include it.
Method: give the player the move that causes the status, then use it on a wild monster through the game's own code path (only the move choice is forced). The probe is one new script, verification/v7-trace/status_probe.py; list it, and the docs/verification.md entry for it, in `files`.
Units: unit 1 builds and validates the generic probe in the scratch directory and leaves a handoff note (script path, usage, what it pokes, the status byte offsets it reads). Then one unit per status in the first-dungeon list: run the probe for that status, record the start value, the turns until the status ends and the trace hash, twice (same hash). A status that cannot be observed (miss, immunity, no suitable target) is reported as such, not claimed.
